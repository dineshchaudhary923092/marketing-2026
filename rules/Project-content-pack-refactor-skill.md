# Skill: Refactor Project Content Packs for Premium Agency Positioning

## Purpose

Use this skill to review and refactor project content packs before publishing them across social media and portfolio platforms.

This skill is for Craftnotion project packs where one project may be published as:

* 1 or more Instagram posts
* 1 or more Facebook posts
* LinkedIn post
* X posts
* Threads posts
* Dribbble post(s)
* Behance project copy
* Pinterest copy
* Website SEO pack

The goal is to make every project pack feel:

* premium
* clear
* strategically positioned
* platform-aware
* trustworthy
* agency-level
* commercially relevant

This is not just editing for grammar.
This is packaging the project so it supports Craftnotion’s positioning as a premium design and development agency.

---

## Core Positioning This Skill Must Protect

Every refactored pack should reinforce these ideas:

* Craftnotion is a serious digital product and website partner
* Craftnotion understands business goals, not just visuals
* Craftnotion builds with strategy, clarity, and execution discipline
* Craftnotion works across websites, web apps, SaaS products, and mobile apps
* Craftnotion is premium, but still practical and commercially clear

If a content line weakens that positioning, rewrite or remove it.

---

## When To Use This Skill

Use this skill when:

* a new project content pack has been drafted
* one project is split into multiple posts
* the content sounds too generic, too decorative, too salesy, or too repetitive
* platform copy feels copy-pasted instead of platform-native
* the pack needs to be aligned with Craftnotion’s premium agency positioning

---

## Input Expected

A project content pack should ideally include:

* project name
* project angle / positioning
* voice direction
* asset mapping by platform
* captions / posts by platform
* hashtags or tags
* dribbble / behance / pinterest copy
* seo title / meta description / slug ideas
* notes or constraints

If any of these are missing, refactor using the available information without inventing false claims.

---

## Non-Negotiable Refactor Rules

### Rule 1: Never exaggerate

Do not invent:

* performance outcomes
* traffic results
* conversion gains
* speed improvements
* compliance, certification, or technical claims
* business results not verified by the project context

If a benefit cannot be verified, position the work around:

* clarity
* structure
* trust
* usability
* digital presence
* communication of the offer or category

### Rule 2: Sound like a premium agency, not a poster caption factory

Avoid:

* vague hype
* empty adjectives
* design-poetry
* “we are thrilled/excited” filler
* overdone startup phrasing
* motivational language

Prefer:

* direct explanation
* clear business framing
* confident but calm language
* strong positioning without chest-beating

### Rule 3: Every post should have one job

A post should mainly do one of these:

* show the project
* explain the project
* show the thinking behind the project
* show why the project matters
* make the agency look more credible

If a post tries to do everything, tighten it.

### Rule 4: The project should be framed around business relevance

Every project pack should answer some combination of:

* what was being designed or built
* what kind of business/category it was for
* what needed to become clearer, stronger, cleaner, or more credible
* what role Craftnotion played

Do not leave the project at “nice visuals.”

### Rule 5: Avoid repetition across platforms

Do not paste the same caption everywhere.
The same project idea should be re-expressed per platform.

---

## Premium Agency Positioning Filters

When refactoring, filter every line through these questions:

1. Does this sound like a serious agency or like a generic creative page?
2. Does this help the reader understand the category, business need, or digital problem?
3. Does this make Craftnotion look structured and commercially aware?
4. Is the language calm and premium?
5. Is there any line here that sounds decorative without adding meaning?

If a line fails 2 or more of these, rewrite it.

---

## What To Remove During Refactoring

Delete or rewrite lines that are:

* too generic
* too self-congratulatory
* repetitive across platforms
* stuffed with adjectives
* not saying anything specific
* trying too hard to sound premium
* too similar to what the slide already says
* overly dependent on CTA language

Examples of weak patterns:

* bold energy, strong visuals, modern feel
* crafted to elevate the brand
* seamless user experience without context
* exciting new project reveal language
* need a better website? visit craftnotion

Not all of these are always wrong, but they should not become default filler.

---

## What To Strengthen During Refactoring

Strengthen lines that clarify:

* industry/category context
* purpose of the website or product
* why the structure matters
* what makes the project relevant to the business
* how the digital presentation was improved
* how the user or buyer benefits from the clarity

Good directions:

* clearer product presentation
* stronger digital credibility
* easier category understanding
* more direct path through the business or offering
* cleaner communication of the brand and product

---

## Refactor Workflow

### Step 1: Understand the project angle

Before rewriting anything, identify:

* what kind of project it is
* who it is for
* what category it belongs to
* what the key digital challenge was
* what kind of positioning is safest and strongest

### Step 2: Define the primary project narrative

Choose one clear narrative for the pack.
Examples:

* industrial website built for stronger product clarity
* premium website designed to increase perceived trust
* dashboard experience built around cleaner workflows
* landing page system designed to explain a technical offer better

Do not use 3 narratives in 1 pack.
Choose one main story and let other details support it.

### Step 3: Map each platform’s job

Refactor based on the platform purpose.

### Step 4: Remove repetition

If two platform captions say almost the same thing, rewrite one of them from a different angle.

### Step 5: Tighten CTAs

Use calm, premium, non-pushy CTAs.

### Step 6: Final quality check

Use the checklist at the end of this skill.

## Platform-Specific Refactor Rules

# LinkedIn

## Role

LinkedIn should make Craftnotion look mature, commercially aware, and capable of handling real business work.

## Best angle

* business framing
* industry relevance
* project context
* strategic thinking
* digital clarity

## Structure

* opening line = business/category challenge
* middle = what the project focused on
* end = why that matters / light CTA

## Keep

* category relevance
* thoughtful explanation
* calm confidence

## Avoid

* too much design language
* too much social-style punchiness
* overly short captions with no context

## Strong LinkedIn directions

* explain why the category needed a different digital approach
* connect clarity to credibility
* mention what kind of structure or messaging mattered

---

# Facebook

## Role

Facebook should feel clearer and more explanatory than Instagram.

## Best angle

* what the project was
* what the brand/business needed
* what changed in the digital presentation

## Structure

* straightforward intro
* 1 to 2 explanatory lines
* calm CTA or no CTA if unnecessary

## Keep

* accessibility
* directness
* clarity

## Avoid

* overly clever lines
* too much jargon
* over-polished “agency language”

---

# Instagram

## Role

Instagram is the visual showroom.
The caption should support the asset, not describe every slide.

## Best angle

* short framing
* project identity
* one strong takeaway
* premium tone

## Structure

* project name or framing line
* what the project is
* one short business/design angle
* optional CTA

## Keep

* concise phrasing
* strong readability
* premium restraint

## Avoid

* long captions repeating slide content
* too many hashtags
* trying to sound inspirational

## Instagram caption principle

Say enough to position the work.
Do not try to explain the entire project in the caption.

---

# X

## Role

X should extract one useful or sharp idea from the project.
It should not read like an Instagram caption pasted into text.

## Best angle

* one observation
* one category truth
* one digital clarity point
* one compact insight from the project

## Structure

* sharp opening line
* quick explanation
* optional mention of project name

## Keep

* insight density
* brevity
* platform-native rhythm

## Avoid

* “check out our latest project” language
* obvious portfolio announcement tone
* hashtag clutter

---

# Threads

## Role

Threads should sound more conversational and reflective than X.

## Best angle

* one observation from the project
* one problem the category often has
* one note about clarity, trust, or usability

## Structure

* soft observation
* supporting thought
* stop

## Keep

* human tone
* practical thinking
* low-friction readability

## Avoid

* sounding like an ad
* corporate posting voice
* copied X posts without softening them

---

# Dribbble

## Role

Dribbble should present the visual direction clearly and searchably.

## Title Rules

The title should contain:

* project name or category
* relevant website/product type
* searchable design term

Examples:

* Industrial Welding Website Design
* B2B Manufacturing Landing Page Design
* SaaS Dashboard UI Design

## Description Rules

* 2 short paragraphs max
* explain what the design is for
* mention the visual/system direction
* keep it useful for viewers, not essay-like

## Tags Rules

* use clear, searchable tags
* mix category + design type + platform type
* do not waste tags on fluff

## Avoid

* generic dribbble buzzwords
* overselling
* bloated descriptions

---

# Behance

## Role

Behance should read like a fuller project presentation.

## Best angle

* project overview
* category challenge
* creative direction
* role or contribution

## Keep

* clearer explanation
* slightly more depth
* calm presentation

## Avoid

* long marketing language
* repeated phrases from social captions
* empty “case study” tone without actual specifics

---

# Pinterest

## Role

Pinterest should be highly searchable and inspiration-friendly.

## Title Rules

* keep it keyword-rich
* name the design type and business category

## Description Rules

* explain what the design is
* include searchable category terms naturally
* support discoverability without keyword stuffing

## Avoid

* vague creative wording
* weak search intent

---

# Website SEO Pack

## SEO Title Rules

* include project name or core category
* keep it clear and searchable
* avoid forced keywords

## Meta Description Rules

* explain what the project is
* include the main category/use case
* mention clarity, credibility, or structure if relevant
* do not overstuff keywords

## Slug Rules

* simple
* descriptive
* lowercase
* no unnecessary filler words

## Handling Projects Split Into Multiple Posts

Some projects should not be treated as one repeated caption with different images.
When a project has multiple post groups, each group should have a distinct role.

### Use these possible split roles

* Post A = overall project / website direction
* Post B = landing pages / system details
* Post C = product/category framing
* Post D = interface or section focus
* Post E = design philosophy / specific insight

### Rule

Each split post must show a different angle.
Do not repeat the same framing with slight wording changes.

### Example structure for a 2-post project split

#### Post 1

* broader project introduction
* what it was for
* what kind of digital presence it aimed to create

#### Post 2

* closer look at one part of the system
* landing page structure
* product presentation
* category clarity

### Example structure for a 3-post project split

#### Post 1

Overall website/product direction

#### Post 2

Section-level or landing-page-level focus

#### Post 3

Insight or takeaway about that category/problem

---

## CTA Guidelines

CTAs should be calm, premium, and secondary.
Do not end every platform post with the same line.

### Good CTA styles

* Need a stronger digital presence for your category?
* Planning a clearer product or website experience?
* Looking for a more structured digital direction?
* Want a website or product experience that feels more credible?

### Good no-CTA endings

Sometimes ending on the project insight is better than using a CTA.
That often feels more premium.

### Avoid

* visit Craftnotion to explore more on every post
* hard-sell urgency
* repetitive “need X? visit Y” endings

---

## Voice Calibration Guide

Use this simple tone scale when refactoring.

### Too weak

* nice
* modern
* visually striking
* elevated
* seamless

### Better

* clearer
* stronger
* more direct
* more credible
* easier to understand
* more structured
* easier to scan

### Too salesy

* game-changing
* revolutionary
* next-level
* unmatched
* world-class

### Better premium tone

* focused
* commercially clear
* built for trust
* category-aware
* structured
* practical

## Output Format For Refactored Packs

When refactoring a project pack, output should follow this structure:

1. Project positioning
2. Core narrative
3. Platform-by-platform rewritten copy
4. CTA recommendations if needed
5. Notes on repetition removed or angle adjustments made

If the project has multiple post groups, clearly label them.

---

## Fast Refactor Checklist

Before approving a refactored project pack, check:

### Positioning

* Does this feel like Craftnotion?
* Does it support premium agency positioning?
* Is the project framed around clarity, trust, structure, or business value?

### Quality

* Is any line generic or padded?
* Is any line exaggerated?
* Is there repetition across platforms?
* Does each platform version feel native enough?

### Split-post logic

* If the project has multiple posts, does each post have a distinct angle?
* Is Post 2 actually different from Post 1?
* Are we reusing the same story too many times?

### CTA

* Is the CTA calm and premium?
* Can one of the posts end without a CTA for a better feel?

If the pack fails 3 or more of these, refactor again.

---

## Final Standard

A strong refactored Craftnotion content pack should feel:

* clear
* premium
* grounded
* category-aware
* commercially useful
* platform-aware
* not repetitive
* not exaggerated

The reader should come away with two impressions:

1. This is a good project.
2. Craftnotion looks like a serious agency that understands what it is doing.
